# 구조 규칙에 예외를 하나 둔다 — 세션 scratchpad 로 향하는 쓰기

파서는 쓰기를 전부 거부해 왔다. 리다이렉트는 `/dev/null` 계열뿐이고 히어독은 무조건 `Deny`다. 명령 이름을 보기도 전에 줄의 *모양*만으로 끊는 구조 규칙이라, 프로젝트 트리에 대해서는 정확히 옳다 — 쓰기는 목적지를 모르면 무해함을 증명할 수 없고, 파서의 일은 "이 줄은 읽기만 한다"를 증명하는 것이다.

한 디렉토리에 대해서만 틀리다. 읽기 전용 계획자에게도 쓸 곳이 하나 필요하다. `explore-model` 은 세션 scratchpad 안에 탐색 하네스를 짓고, 모델이 교정될 때마다 고쳐 다시 돌린다. 그 스킬은 재실행이 값싸다는 전제 위에 서 있다 — "틀린 불변식의 비용은 탐색 재실행 몇 초라, **매 호출의 승인 왕복보다 싸다**". 그런데 실제로는 매 재실행이 승인 왕복이었다. 6회 반복 세션(탐색 → 하네스 작성 → 실행 → 판독)을 훅에 그대로 먹여 세어 보면 bash 24회 중 **12회가 프롬프트**다. 작성 6회, 실행 6회.

[ADR-0003](0003-the-judgment-log-is-a-regression-suite.md) 의 판정 로그가 이게 가설이 아님을 확인해 준다. 308건을 재생하면 이 변경으로 자동 허용으로 넘어가는 줄이 정확히 하나 있다 — `gh issue view 141 --repo … --json … > <scratchpad>/issue141.json`. 2026-08-17 다른 프로젝트 세션에서 읽기 전용 `gh` 가 결과를 scratchpad 에 담으려다 막힌 기록이다.

그래서 예외를 하나 판다. **목적지가 세션 scratchpad 안이라고 증명되는 쓰기**만 허용한다. 경로 모양이 하네스에 의해 고정돼 있어서 증명이 가능하다 — `/tmp/claude-<uid>/<project-slug>/<session-uuid>/scratchpad/…`. 접두어 검사가 아니라 깊이 정확히 5로 쪼개 확인하고, `..` 가 어디든 있으면 즉시 탈락시킨다. 히어독은 이 리다이렉트가 이미 선 줄에서, 구분자가 따옴표로 묶였을 때만 본문을 데이터로 건너뛴다.

**거기서 멈춘다. 쓴 것을 실행하는 것은 예외가 아니다.**

## Considered Options

**플랜 모드를 오토모드로 바꾼다.** 마찰의 근원이 플랜 모드니 모드를 바꾸자는 안이다. 같은 9개 케이스를 `permission_mode: "auto"` 로 먹여 보면 훅이 첫 줄에서 빠져나가 **9건 전부 판정이 없다** — `rm -rf src/` 와 프로젝트 파일 쓰기까지. 보증이 "파서가 증명한 읽기 전용"에서 "모델 판단"으로 바뀐다. 이 저장소가 존재하는 이유를 지우는 안이라 기각했다.

**scratchpad 안 스크립트의 실행까지 허용한다.** 프롬프트가 12회에서 **0회**로 떨어진다. 보안 회귀 8종(프로젝트 파일 쓰기, `rm -rf`, `git commit`, 경로 탈출, 따옴표 없는 히어독, `python3 -c`, `bash <하네스>`, scratchpad 밖 `/tmp` 쓰기)도 **전부 그대로 막힌다.** 개별 케이스만 보면 이쪽이 우승이다.

시퀀스로 돌리면 뚫린다. 히어독 본문은 데이터라 파서가 읽지 않는다 — 본문이 `open('<프로젝트>/src/state.ts','w')` 여도 통과한다. 그리고 이 안은 그것을 실행까지 허용한다. **작성 ALLOW + 실행 ALLOW = 플랜 모드 안에서 임의 코드 실행.** 단일 케이스 테스트로는 잡히지 않고 두 호출을 이어야 드러나므로, 회귀 스위트가 초록이어도 안전하다는 뜻이 아니었다. 기각의 근거가 이 조합이다.

**접두어 검사로 충분하다.** `/tmp/claude-` 로 시작하면 허용하자는 안. `..` 와 깊이를 보지 않으면 `/tmp/claude-x/../../../home/…` 로 그대로 걸어 나간다. 깊이 정확히 5 + `..` 금지 + uid 자리 숫자 검사로 대체했다.

**정규식으로 경로를 판정한다.** 짧아지지만 `re` 를 모듈 최상위로 끌어올려야 한다. 이 모듈은 플랜 모드의 **매 Bash 호출마다** 돈다 — 훅이 서브프로세스를 피하려 애쓰는 것과 같은 이유로, `re` 는 828 행에서 함수 안 지연 임포트로 남아 있다. 그 규율을 이 검사가 깨게 둘 이유가 없어 문자열 연산으로 썼다.

## Consequences

- **프롬프트가 12회에서 6회로 준다.** 남는 6회는 전부 하네스 *실행*이다. 결함이 아니라 제자리다 — 스크립트 내용은 파서가 증명할 수 없는 유일한 지점이라, 사람이 서 있어야 할 곳이 정확히 거기다.
- **이 수치는 경로를 리터럴로 쓴다는 전제 위에 있다.** 예외는 리다이렉트 타겟 토큰을 *쓰여 있는 그대로* 읽고 토크나이저는 아무것도 전개하지 않으므로, `S=<경로>; cat > "$S/h.py"` 는 같은 디렉토리로 향하면서도 계속 프롬프트다. 대입을 해석하는 안은 검토하고 기각했다 — 판정 로그 324건(쓰기 거부 115건) 기준으로 리터럴 형태가 9건, 같은 줄 변수 형태가 3건이라 얻는 것이 3건인데, 그 대가가 파서에 의도적으로 두지 않은 심볼 테이블이다("대입만 있는 세그먼트는 셸 변수를 설정할 뿐 아무것도 실행하지 않는다"). 실패 방향이 결정적이다: 지금은 읽지 못하는 형태를 만나면 **묻고**(안전), 해석기가 하나를 잘못 읽으면 **허용한다**(안전하지 않다). 마찰은 반대편에서 답한다 — planner 에게 하네스 경로를 리터럴 절대 경로로 쓰라고 지시했다. 호출 간 대입은 아예 규칙이 필요 없다: Bash 툴이 호출 사이에 셸 상태를 나르지 않으므로 앞 호출의 `S=` 는 다음 호출에서 빈 값이다. 같은 줄 형태만이 의미가 있었다. 회귀 스위트가 이 경계를 고정한다.
- **12→6 은 맞지만 대표적이지 않다 — 실제 계획자는 그 형태로 쓰지 않았다.** 위 수치는 합성 6회 반복 루프로 쟀고, 그 루프의 쓰기는 전부 `cat > <리터럴 경로>/model.py <<'EOF'` 였다. 나중에 `fable-planner` 를 plan mode 에서 실제 작업(16분, 툴 17회)에 붙여 판정 로그 증분을 봤더니 **거부 9건 중 이 예외가 막아줄 수 있었던 것이 하나도 없었다.** 계획자는 하네스를 리다이렉트로 쓰지 않는다 — `mkdir`·`cp` 로 트리를 만들고 `python3 - <<'PYEOF'` 로 **stdin 에** 히어독을 먹였다. 리다이렉트가 없으니 예외가 설 자리가 없고, 파일을 만드는 `mkdir`·`cp` 는 명령 이름으로 거부되므로 애초에 관할 밖이다. 나머지 거부는 `bash`·`python3`·`docker`, 그리고 scratchpad 가 아닌 `~/.claude/plans/` 로의 리다이렉트였다. 허용된 호출은 로그에 남지 않으므로 "예외가 0번 발동했다"고까지는 말할 수 없고, **거부된 9건 중 해당 사례가 없었다**는 것이 잰 값이다. 예외를 넓힐지는 별개 판단이지만, 넓힌다면 근거는 이 관측이지 12→6 이 아니다. (2026-09-03 실측. `judgments.jsonl` 의 09:11–09:28 구간.)
- **훅은 서브에이전트 Bash 호출에 붙는다 — 확정.** 위 측정의 부산물이다. 계획자의 명령이 파서를 타고 거부돼 로그에 남았다. 다만 그 완화가 닿는 대상은 "plan mode 의 서브에이전트"가 아니라 **"scratchpad 쓰기를 자기 정의에서 허가받은 서브에이전트"** 다. 같은 조건에서 일반 서브에이전트(general-purpose)는 쓰기를 **호출조차 하지 않았다** — plan mode 시스템 메시지를 받고 스스로 멈춘다. plan mode 의 제약이 서브에이전트에게는 하드 차단이 아니라 프롬프트 수준의 자기 검열로 작동하기 때문이고, `fable-planner` 가 시도할 수 있었던 것은 정의에 "탐색 하네스는 세션 scratchpad 안에서만 작성·실행한다"가 박혀 있어서다.
- **구조 규칙이 처음으로 조건부가 됐다.** 히어독은 이제 무조건 거부가 아니다. 다만 본문 소비는 토큰 스트림에서 본문을 빼는 것뿐이라, 남은 토큰은 여전히 모든 규칙을 통과해야 한다. `bash <<'EOF'` 는 `bash` 에서 죽고, `rm -rf src/ > <scratch>/out.txt` 는 `rm` 에서 죽는다. 본문을 실행할 수 있는 명령(`bash`, `sh`, `python3`, `tee`)은 전부 `KNOWN_EXECUTORS` 라, 본문은 읽기 전용 명령에만 닿는다.
- **심볼릭 링크를 막는 것은 경로 검사가 아니라 링크를 심는 쪽이다.** `is_scratch_path` 는 어휘적이라 경로를 해석하지 않는다 — scratchpad 안에 밖을 가리키는 링크가 있으면 그리로 쓴다. 그래서 링크를 심는 18개 경로를 재 봤고 전부 거부됐다. 다만 **거부의 강도가 둘로 갈린다.** `ln`·`cp -s`·`install`·`python3`·`unzip`·`git checkout`·`git clone`·`git worktree add`·`gh repo clone` 은 구조적으로 닫혀 있다 — `llm_second_opinion` 이 `rule != UNKNOWN_COMMAND_RULE` 이면 즉시 반환하므로 분류기의 YES 가 이 줄들에 닿지 않는다. 반면 `tar`·`rsync`·`cpio`·`7z`·`bsdtar`·`busybox` 는 파서가 이름을 모르는 것들이라 **분류기의 판단이 유일한 관문**이다. 실제로 물어보니 7건 전부 거부했지만(2026-09-02 실측) 그건 표결이지 증명이 아니다. 이쪽을 넘기려면 `unzip` 이 받은 것과 같은 대접 — `tar tf` 는 읽고 `tar xf` 는 쓰므로 이름 승격이 아니라 플래그 체커 — 이 필요하다. 회귀 스위트의 `symlink` 버킷이 이 구분을 고정한다.
- **히어독이 리다이렉트보다 앞서는 형태는 인식하지 않는다.** `cat <<'EOF' > <scratch>/h.py` 는 계속 프롬프트다. 토크나이저가 아직 읽지 않은 리다이렉트로는 플래그가 설 수 없고, 그 방향으로 보수적인 편이 낫다.
- **회귀 스위트가 483 에서 523 으로 는다.** 새 `scratchpad` 버킷 23건이 예외의 양쪽 — 허용되는 쓰기와 허용되지 않는 실행 — 그리고 리터럴 경로라는 경계를 같이 고정한다. 실행 쪽을 지우면 위에서 기각한 안이 되므로, 그 6건이 이 결정의 경계선이다. `symlink` 버킷 17건은 이 예외를 닫아 두는 것이 경로 검사가 아니라 링크를 심는 쪽의 거부라는 사실을 고정한다.
- **판정 로그 308건 재생 결과:** 자동 허용으로 넘어간 것 1건(위의 `gh issue view`), 사유가 바뀐 것 7건. 뒤엣것은 리다이렉트에서 조기에 끊기던 줄이 이제 그 다음 진짜 문제(`git fetch`, `cd` 뒤 git, `mkdir`)에서 끊기는 것으로, 전부 여전히 거부다. 나머지 300건은 무변화.
- ADR-0003 이 "이 저장소에서 정확성은 리뷰 대상이 아니라 **측정 대상**"이라고 한 것의 첫 적용 사례다. 이 변경은 어느 단계에서도 추론으로 결정되지 않았다 — 마찰의 크기도, 오토모드 기각도, wide 안의 구멍도, 전부 훅에 입력을 먹여 나온 판정으로 갈렸다.
